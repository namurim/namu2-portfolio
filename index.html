PERSONAL PROJECT

개인 프로젝트 / Face Tracking & 3D Animation

Avatar Tracker — 얼굴 추적 테스트

프로젝트 개요

카메라나 영상 파일 속 얼굴의 움직임을 읽어 간단한 3D 아바타에 반영하는 브라우저 기반 테스트 도구입니다. 얼굴 특징점과 표정 수치, 아바타 반응을 한 화면에 표시해 실제 얼굴의 변화가 어떤 값과 움직임으로 연결되는지 확인할 수 있도록 만들었습니다. 아바타는 Three.js 도형으로 직접 구성했습니다.

MediaPipe · 얼굴에서 정보 얻기

MediaPipe는 Google의 머신러닝 기능을 앱에서 사용할 수 있게 해주는 도구 모음입니다. 이 프로젝트에서는 Face Landmarker의 사전학습 모델을 사용해 영상에서 얼굴 특징점, 눈 감김·입 벌림·미소 등의 표정 값과 고개 방향을 얻습니다. 화면에는 478개 특징점과 주요 표정 수치를 표시합니다. 모델을 새로 학습하지 않고 브라우저에서 추론합니다.

Three.js · 추출한 값을 움직임으로 표현하기

Three.js는 브라우저에서 3D 장면을 만들고 그리는 JavaScript 그래픽 라이브러리입니다. 분석된 정보를 눈에 보이는 움직임으로 표현하는 역할을 맡습니다. 구 형태의 얼굴에 눈과 입을 구성하고, MediaPipe가 반환한 값을 머리 회전·눈 크기·입 높이와 입꼬리 곡선에 연결했습니다.

처리 흐름

카메라·영상 입력 → 유효한 프레임 준비 → MediaPipe 얼굴 분석 → 특징점·표정·방향 추출 → Three.js 아바타와 수치 표시

주요 구현 내용

  • 얼굴 특징점과 눈·입·윤곽 표시
  • 고개 방향을 아바타 회전에, 눈 감김을 각 눈의 크기에 연결
  • 입 벌림과 미소에 따라 입의 높이·너비·입꼬리 곡선을 갱신
  • 표정 값 보간으로 아바타 움직임을 부드럽게 연결

얼굴 움직임과 아바타 반응

얼굴이 기울어지고 웃는 영상 프레임에서 아바타의 고개와 입꼬리가 함께 변하는 모습을 확인했습니다. 같은 프레임의 수치 화면에서는 미소 값이 0.87로 표시됩니다.

눈 감김과 표정 변화 확인

눈을 감은 프레임에서는 왼쪽·오른쪽 눈 감김 값이 각각 0.67·0.63으로 나타나며 아바타의 눈도 얇아집니다. 다른 프레임에서는 눈 감김 값이 낮아지고 미소 값이 0.47로 바뀌며 눈이 열리고 입꼬리가 올라가는 모습을 볼 수 있습니다.

배운 점

  • 사전학습된 MediaPipe Face Landmarker 모델을 불러와, 실제 영상에서 얼굴 특징점과 표정 값이 추출되는 과정을 확인했습니다.
  • 추출한 값을 Three.js 아바타에 연결해 얼굴 움직임에 따라 눈과 입의 모양, 고개 방향이 변하도록 구현했습니다.
  • 실제 얼굴의 변화와 모델 출력, 아바타 반응을 함께 보며 사전학습 모델의 결과를 직접 활용하는 흐름을 익혔습니다.

PERSONAL PROJECT / 개인 프로젝트

개인 프로젝트 / Agent + MCP · Public API Integration

DayPlan — Agent·MCP 기반 가족 여행 플래너

프로젝트 개요

출발지와 여행지, 날짜, 가족 구성과 여행 취향을 입력하면 두 가지 여행 일정을 제안하는 국내 가족 여행 플래너입니다. 기획 에이전트가 여행 정보를 바탕으로 초안을 만들고, 검토 에이전트가 일정과 근거를 확인해 수정 요청을 돌려주는 구조로 구성했습니다. MCP 서버에 공공 API 조회 기능을 도구로 연결하고, 조사·검토 과정과 최종 결과를 웹 화면에서 확인할 수 있도록 구현했습니다.

주요 개발 내용

  • 출발지·여행지·날짜, 성인 수·아동 나이, 고령자 동반·유모차·휠체어 등 가족 조건 입력
  • 자연·바다, 문화·역사, 실내 체험, 맛집·휴식 등 여행 취향과 이동 수단 선택
  • 관광지·음식점·숙소 후보, 교통편과 날씨를 공공 API에서 조회
  • 기획 에이전트의 초안 생성과 검토 에이전트의 피드백에 따른 최대 2회 수정
  • 정보 수집 → 일정 기획 → 검토·수정 진행 상태와 조회 이력 표시
  • 여유로운 일정·관광 중심 일정 탭과 두 일정 비교, 날짜별 타임라인 구성
  • 정보 출처와 확인 필요 항목 표시, 최근 일정 불러오기 및 모바일 화면 지원
담당 역할

가족 여행 입력·결과 화면, Python 백엔드, 기획·검토 에이전트와 프롬프트, MCP 서버·클라이언트 및 공공 API 조회·응답 처리 구현

기획·검토 에이전트 구성

두 에이전트는 OpenRouter를 통해 모델을 호출하며, 역할별 지침과 전달받는 정보를 다르게 구성했습니다. 기본 여행 정보는 먼저 수집하고, 이후에는 모델이 필요한 추가 도구를 선택하면 코드가 MCP를 통해 실행하고 결과를 다시 모델에 전달합니다.

01 · PLANNER

기획 에이전트

가족 구성과 취향, 수집한 여행 정보를 바탕으로 여유로운 일정과 관광 중심 일정을 작성합니다. 검토 피드백을 받으면 필요한 정보를 추가 조회하고 초안을 수정합니다.

02 · REVIEWER

검토 에이전트

요청 조건과 일정이 맞는지, 교통편·운영 정보·가족 편의에 확인할 점이 있는지 살펴봅니다. 문제가 있으면 구체적인 수정 요청을 전달하고, 남은 불확실성을 결과에 표시합니다.

여행 조건 입력→정보 수집·초안 작성→검토·수정 요청→필요 시 재작성→여행안 2개 표시

실행 순서와 최대 수정 횟수는 백엔드 코드에서 관리합니다. 최대 2회 수정한 뒤에도 해결되지 않은 내용이 있으면, 검증 완료로 처리하지 않고 확인 필요 상태로 남깁니다. 모델 응답은 구조화된 형식으로 받아 입력·출력 데이터를 검증합니다.

MCP란 무엇인가요?

MCP(Model Context Protocol)는 AI 애플리케이션이 외부 도구와 데이터에 연결할 때 사용하는 표준 프로토콜입니다. 이 프로젝트에서는 장소 검색, 교통편·날씨 조회 함수를 MCP 서버의 도구로 제공하고, 백엔드의 MCP 클라이언트가 이를 호출합니다. MCP 서버는 모델의 판단 결과를 받아 실제 공공 API에 요청하고, 조회 결과를 에이전트가 사용할 수 있는 형태로 돌려줍니다.

에이전트 · 조회할 정보 판단MCP 클라이언트 ↔ MCP 서버 · 도구 호출공공 API · 원본 데이터 조회

모델은 계획과 검토를, MCP는 도구 연결을, 외부 API는 데이터 조회를 담당합니다. MCP 서버와 클라이언트는 로컬 stdio(표준 입출력)로 연결하며, API 인증키는 서버에서 관리해 화면이나 모델 입력에 포함하지 않도록 구성했습니다.

사용 API 정보공공 API 8종 + 모델 API

각 항목의 제목을 누르면 공식 문서·활용 신청 페이지로 이동합니다. 여행 비용 계산은 제외하고, 일정과 장소·교통·날씨 정보를 만드는 데 활용했습니다.

조사·검토 진행 과정

정보 수집, 일정 기획, 검토·수정 단계를 화면에 표시하고 준비 과정 목록에서 운영 정보 확인·교통편 조회·추가 검색 이력을 확인할 수 있도록 구성했습니다.

두 가지 일정과 날짜별 결과

여유로운 일정·관광 중심 일정 탭과 두 일정 비교 기능을 제공합니다. 방문 순서와 시간, 이동 메모, 숙소 후보를 카드로 표시하고 항목별 정보 출처와 확인할 내용을 함께 확인하도록 구성했습니다.

데이터 확인과 현재 범위

HTTP 응답뿐 아니라 API의 결과 코드와 빈 데이터도 구분하고, 서로 다른 지역·역·터미널·예보구역 코드와 예보 발표 시각을 처리했습니다. 숙소는 후보 정보로 제공하며 객실 재고·잔여 좌석·시내 환승 경로는 별도 확인이 필요합니다. 예보·배차 조회 범위 밖의 정보와 검토에서 해결하지 못한 항목을 확정 사실로 표시하지 않도록 구성했습니다.

배운 점

  • 같은 모델도 역할별 지침과 입력·출력 형식을 나누면 기획과 검토의 책임을 분리할 수 있음을 확인했습니다.
  • MCP 도구와 외부 API 호출을 분리해, 모델의 판단과 실제 데이터 조회가 이어지는 흐름을 구현했습니다.
  • 지역·역·터미널·예보구역의 서로 다른 코드 체계와 예보 발표 시각을 정리하며, 에이전트가 사용할 입력값을 코드에서 보완했습니다.
  • 반복 횟수를 제한하고 해결되지 않은 항목을 남겨, 검토가 끝났다는 이유만으로 모든 정보를 확정하지 않도록 구성했습니다.
